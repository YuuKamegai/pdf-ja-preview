# PDF 日本語プレビュー（ローカル Web アプリ）

英語の PDF を、原文と日本語訳を左右に並べて読むためのローカルアプリです。文書は
この machine から出ません。抽出も翻訳もローカルで動きます。

- 原文は PDF.js でそのまま描画します。図も数式も元の見た目のままです。
- 訳文は段落ごとに出します。原文の段落を押すと、対応する訳が選ばれます（逆も同じ）。
- 翻訳はローカルの Ollama です。見ているページから順に訳します。

## できないこと（初期版）

| できないこと | 補足 |
|---|---|
| 文字が入っていない PDF（スキャン画像） | OCR は入れていません。`no-text` として「文章を抽出できません」と出します |
| 表のセルの翻訳 | 表は原文の切り抜きを見せます |
| 図の中の文字の置き換え | 図の切り抜きを見せます。図中の文字は訳さず、図の下に畳んで残します |
| 数式の再組版 | 数式は原文のまま残します |
| 翻訳済み PDF の書き出し | 画面で読むためのものです |
| URL から取得 | 手元のファイルだけです |
| 3 段組み以上・縦書き・横倒しのページ | 一段組みと二段組みが対象です |

品質保証の範囲も限られます。数値・引用番号・DOI/URL・`$...$` などで明示された数式・
英数字が混ざった識別子は、翻訳の前に退避して、返ってきたものを突き合わせてから戻します。
**区切り記号の無い数式や、英字だけの識別子は自動では見分けられません。** その部分は
保証の対象外です。原文と見比べてください。

## 用意するもの

| もの | 確認した版 | なぜ要るか |
|---|---|---|
| Node.js | 24.15.0 | サーバーと画面 |
| Docker Desktop | Engine 29.4.0 | 抽出（Docling）をコンテナで動かす |
| Ollama | 起動していること | 翻訳 |
| Python | 3.13 | 抽出まわりの試験だけ（本体には不要） |

### なぜ抽出だけコンテナなのか

この machine は Windows の **Smart App Control が Enforce** で、`torch` のような
未署名のネイティブライブラリを読み込めません（`WinError 4551`）。Docling は torch に
依存するため、Windows のローカル環境では動かせませんでした。

抽出だけをコンテナへ閉じ込め、サーバーとの境界は「stdout に JSON 一件」に保っています。
Smart App Control の無い環境では、`PDF_JA_PYTHON` を指定すればローカルの Python で
同じワーカーを動かせます（コンテナは不要になります）。

## セットアップ

Docker Desktop を起動してから、一度だけ実行します。

```powershell
pwsh -File scripts/setup-pdf.ps1
```

これで次が揃います。

- 抽出イメージ `pdf-ja-extractor:1`（レイアウトモデルをイメージへ焼き込み済み）
- `python/requirements.lock.txt`（イメージ内で解決した実バージョン）
- `.venv-pdf`（正規化と前検査の試験用。Docling は入れません）
- `.venv-pdf-fixtures`（合成 fixture を作る用）

イメージの構築では PyPI と Hugging Face からダウンロードします。**実行時は
`--network none` で回すので、原文を扱っている間に外へ出ることはありません。**

## 起動

```powershell
npm run build:web
npm run start:web
```

`http://127.0.0.1:7391/` が開きます。`--open` を付けると既定のブラウザで開きます。

```powershell
node dist-web/server.cjs --open
```

## 設定（環境変数）

| 変数 | 既定 | 意味 |
|---|---|---|
| `PDF_JA_PORT` | `7391` | 待ち受けポート。`127.0.0.1` にだけ bind します |
| `PDF_JA_MODEL` | `qwen3.5:9b-q4_K_M` | 既定のモデル。拡張側と同じ |
| `PDF_JA_OLLAMA_ENDPOINT` | `http://127.0.0.1:11434` | ループバック以外は拒否します |
| `PDF_JA_DATA_DIR` | `%LOCALAPPDATA%\pdf-ja-preview` | キャッシュと一時ファイルの置き場所 |
| `PDF_JA_EXTRACTOR_IMAGE` | `pdf-ja-extractor:1` | 抽出イメージ |
| `PDF_JA_PYTHON` | （空） | 指定するとコンテナではなくローカル Python で抽出します |
| `PDF_JA_MODELS_DIR` | `/models` | 事前取得したモデルの置き場所 |
| `PDF_JA_EXTRACTION_TIMEOUT_MS` | `600000` | 抽出の打ち切り |
| `PDF_JA_REQUEST_TIMEOUT_MS` | `120000` | 1 ブロックあたりの翻訳の打ち切り |
| `PDF_JA_STATIC_ROOT` | `./dist-web` | 画面の配信元 |

## 上限

| 何 | 既定 |
|---|---|
| PDF の大きさ | 50 MiB。超えた時点で受け取りをやめます |
| ページ数 | 300。変換を始める前に拒否します |
| 抽出の同時実行 | 1 |
| 翻訳の同時実行 | 1（サーバー全体で） |
| 1 ブロックの分割単位 | 1500 文字 |

## 保存先と消し方

既定は `%LOCALAPPDATA%\pdf-ja-preview` です。

```
%LOCALAPPDATA%\pdf-ja-preview\
  docs\<文書のsha256>\document.json   抽出結果
  docs\<文書のsha256>\tr\<鍵>.json    訳文
  tmp\<サーバーID>\*.pdf              閲覧中の PDF（サーバーを閉じると消えます）
```

- 画面の **「保存した訳を消す」** で、その文書の訳だけ消せます。
- **「閉じる」** で、その文書の一時 PDF をサーバーから外します。
- フォルダごと消しても問題ありません。次に開いたときに取り直します。

異常終了で一時 PDF が残っても、次にサーバーを起動したときに回収します。生きている
別のサーバーが使っているものは残します。

## 動かなくなったとき

| 症状 | 見るところ |
|---|---|
| 「抽出に失敗」で止まる | Docker Desktop が動いているか。`docker run --rm pdf-ja-extractor:1 --help` |
| 訳が出ない・「失敗」が並ぶ | Ollama が動いているか、モデル名が合っているか。`curl http://127.0.0.1:11434/api/tags` |
| 「文章を抽出できません」 | 文字が入っていない PDF です。初期版では扱えません |
| 「図や表の中の文字 N 件は訳しません」 | 仕様です。図の下に畳んであります |
| ページの位置がずれる | 「ページの寸法が一致しません」の警告が出ていれば、位置同期は切ってあります |
| 画面が真っ白 | `npm run build:web` を先に実行してください |

## 作りの要点

- サーバーは `127.0.0.1` にだけ bind し、`Host` を許可した名前に限り、`Origin` が
  あれば同一 origin だけ通します。API には起動時に作った token を専用ヘッダーで
  要求します。token は起動 HTML にだけ埋め、ログには出しません。
- PDF.js の worker・CMap・標準フォント・wasm はすべて `dist-web/pdfjs/` へ複製します。
  実行時に CDN を見に行きません（`connect-src 'self'`）。
- 読み順は抽出器の本文ツリーから取ります。座標の縦位置では並べません。二段組みでは
  右段の先頭が左段の続きより上に来るため、縦位置で並べると順序が壊れます。
- 抽出の座標は CropBox の原点を引いた**回転後**の空間で来ます。中間形式では回転前に
  戻してから 0..1 にします（PDF.js の `page.view` に合わせるため）。
