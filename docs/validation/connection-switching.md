### この変更で足した主な回帰試験

**接続の検証（`connection.test.ts`）**

- Ollama はループバック限定で、`cloud-allowed` を指定できない。
- クラウドは送信許可が無ければ保存できない。
- Azure は公式 2 ホストの `/openai/v1` へ正規化し、それ以外を拒否する。
- OpenAI 互換は `https` のみ。ループバックに限り `http` を許す。
- 画面へ出す形に鍵が入らない。
- provider か送信先が変われば「別の送信先」と判定する（鍵の破棄規則の土台）。

**保存と移行（`settings-store.test.ts`）**

- v1（`apiKey` だけの形）から移行し、**暗号文をそのまま引き継ぐ**。
- 移行は一度だけ。二度目に種を使おうとすると試験が落ちる。
- より新しい `version` は**上書きせず**起動を止める（ファイルが元のままであることも確認）。
- 壊れた v2、存在しない選択名からの回復。
- 送信先を変えたら鍵を破棄し、モデルだけ変えたときは保つ。
- 最後の 1 件は消せない。選択中を消したら先頭を選ぶ。
- 一覧にも `settings.json` にも平文の鍵が出ない（実 DPAPI）。
- 平文で書かれた鍵と復号できない鍵は、どちらも未登録として扱う。

**API（`http.test.ts`）**

- 一覧・追加・更新・削除・選択・接続テストの契約。
- 登録した鍵がどの応答にも現れない（一覧・文書・セッション・起動 HTML を全部見る）。
- 制御文字（`\n` / `\r\n`）と空白だけの鍵を 400 で断り、断り文に値を含めない。
- ローカル provider を選んでいる間はクラウドへ 1 バイトも出ない。
- 鍵未登録のクラウド接続ではセッションを作れない（409 `no-api-key`）。
- `/api/settings/api-key` が 404 になっている（削除の確認）。
- 接続名を `encodeURIComponent` して道筋へ載せられる。

**切り替え（`session.test.ts` / `http.test.ts`）**

- 切り替えで世代が上がり、新しい送信先とモデルで訳し直す。
- **古い接続への実行中の翻訳が打ち切られる。**
- 同じ接続・同じモデルなら何もしない（選び直しで訳し直さない）。
- `POST /api/sessions` に `model` を送っても無視する。

**移行（`main.test.ts`）**

- クラウドの環境変数から移行すると、切り替え先としてローカル接続も一緒に作る。
- ローカルの環境変数からは 1 件だけ作る。
- 許可の無いクラウドの環境変数は移行できない。
- 鍵が未登録でもサーバーは起動して画面を配信する。

**実画面（`preview.spec.ts`、Edge）**

「鍵の無いクラウド接続へ切り替え → 理由が画面に出る → 管理画面で鍵を登録 → 入力欄は
空に戻る → そのまま訳が出て送信先が表示される → ローカルへ戻すと表示が消え、
キャッシュから訳が戻る」まで通しました。翻訳は fixture の固定応答なので、この試験でも
外部へは 1 バイトも出ていません。

## 2. 計画から変えたこと

- **Task 3 と 4 を 1 コミットにまとめた。** Task 3 の試験が `Session.setConnection()` を
  通るため、分割すると試験が走りませんでした。
- **一覧の応答に `baseUrl` を足した。** 計画では `target`（ホスト名）だけでしたが、それだと
  編集のたびに送信先 URL を打ち直させることになり、打ち間違いで鍵が破棄されます。
  `baseUrl` に鍵は含まれないので、画面へ返して差し支えありません。
- **E2E の「モデルを変えると訳し直す」を削除した。** モデル欄そのものが無くなったため、
  接続の切り替え試験へ置き換えました。

## 3. 途中で見つけて直した不具合

- 切り替え時に「API キーが登録されていません」を出した直後、同じ関数がバナーを空にして
  いました。使えない接続の理由が一瞬で消える不具合で、E2E で見つけました。直したうえで、
  「接続の警告と同じ文のときだけ消す」形にし、他の理由で出ているバナーを巻き込まないよう
  にしています。
- 切り替えの打ち切り試験が永久に返らない状態でした。切り替えで訳し直しが始まり、試験の
  偽 translate が打ち切られるまで解決しないためです。`scheduler.idle()` を待つのをやめ、
  打ち切りそのものを待つように直しました。

2. ローカルの接続で PDF を 1 本訳す。

4. ローカルへ戻し、**訳し直しにならず即座に戻る**ことを確認する（キャッシュが効いている）。

## 5. 既知の限界

- 接続の並べ替えと、複数接続の同時使用には対応していません。
- LAN 上の Ollama（Use-LLLM の `lan_allowed`）は入れていません。Ollama はループバック
  限定のままです。
- ループバックの OpenAI 互換サーバーにも「クラウド送信を許可」のチェックが要ります。
  実際には外へ出ませんが、`assertSendable()` の分岐を 1 本に保つための割り切りです。
