# PDF 日本語プレビュー Web アプリ設計

- 日付: 2026-09-17
- 状態: 設計レビュー待ち。実装未着手。
- 合意済み: ローカル Web アプリ、原文 PDF と日本語の左右表示、学術論文と一般文書が対象、ローカル LLM を使用。

## 1. 目的と初期版

英語 PDF を開き、原文と対応する日本語を見比べて読める単一ユーザー向けアプリを作る。
初期版は文字選択可能な一段組み・二段組み PDF を対象とする。
本文、見出し、箇条書き、キャプション、脚注を翻訳する。
図・表・独立数式は日本語側にも原文の該当領域を画像表示し、キャプションは別ブロックとして訳す。
参考文献、ヘッダー、フッターは抽出器が識別したものを原文のまま折りたたんで表示する。
表のセル翻訳、図中の文字置換、数式の再組版、翻訳済み PDF の出力、OCR、URL からの取得は初期版の対象外。
分類を誤った内容も原文を確認でき、翻訳対象の文章は抽出結果を確認して再翻訳できる。

## 2. 技術構成と選定理由

- ブラウザ: TypeScript + PDF.js + CSS。初期版は UI フレームワークを追加せず、左右の表示・状態管理をモジュールに分ける。
- ローカル HTTP サーバー: Node.js 24 + TypeScript。ブラウザと同一オリジンで API と静的ファイルを提供。
- PDF 抽出: 専用 Python 仮想環境内の Docling。Node がワーカープロセスとして起動する。
- 翻訳: Ollama のローカル API。既存の通信処理を共通化して利用する。
- 保存: ユーザーのローカルアプリデータ配下に文書単位の抽出 JSON と翻訳キャッシュを保存。
- 配置: 同じリポジトリの `web/` と `python/` に追加し、VS Code 拡張とは別コマンドで起動。

PDF.js のみで読み順の復元まで行う案より、二段組みや図表を扱う Docling の文書構造を利用する案を採用する。
Python 単独の Web サーバー案に比べ、Node を残すことで既存の Ollama 通信と TypeScript の検証資産を再利用できる。
ただし Docling は未導入であり、この環境での依存関係・実 PDF の抽出精度・速度は未検証。
Python のバージョンは既存の 3.14 を前提にせず、依存パッケージの対応をインストール前に確認し専用環境を固定する。
抽出は初期版では CPU を使用し、Ollama が使用する GPU のメモリと競合しにくくする。
モデルはセットアップ時に取得し、文書を読む実行時には外部サービスや CDN を利用しない。

## 3. 画面と操作

上部にファイル選択、文書名、ページ移動、拡大縮小、モデル設定、翻訳の一時停止・再開、処理状態を置く。
左は原文 PDF の現在ページ、右は対応する段落と画像の縦スクロール表示とする。
前後ボタンとページ番号入力で移動する。初期版はページ単位の同期とし、左右のスクロール量を比例連動させない。
右の段落を選ぶと左の対応領域を強調する。左の領域を選ぶと右の対応ブロックへ移動する。
ページをまたぐ項目は一つの論理ブロックとして全出典を保持し、該当各ページから同じ訳文を参照できる。
複数領域が重なるときは、最小領域を優先し、候補を切り替えられるようにする。
ズーム・ページ回転でも対応領域の表示位置を維持する。
座標のないブロックは「位置情報なし」と明示し、座標を推測して強調表示しない。

PDF の原文表示を先に開始し、抽出中はその状態を表示する。
初期版の Docling 処理は文書全体の抽出完了後に段落を公開する。ページごとの抽出ストリーミングは約束しない。
抽出完了後は日本語側にも原文を表示し、訳せた段落から差し替える。

## 4. データと対応づけ

独自の中間形式 `pdf-document.v1` を設け、Docling の型をそのままフロントエンドへ公開しない。

- 文書: PDF バイト列の SHA-256、抽出器と設定の識別情報、ページ寸法・回転、ブロック一覧、警告。
- ブロック: 文書内 ID、種別、読み順、原文、見出し文脈、翻訳対象フラグ、出典領域の配列。
- 出典領域: 1 始まりのページ番号、左上原点・回転適用前のページ寸法に対する正規化座標、原文内の文字範囲（得られる場合）。
- 翻訳: ブロック ID、原文ハッシュ、モデル・プロンプト設定、状態、訳文、エラー。

Docling の body ツリーの順序を使い、単純な Y 座標ソートで二段組みを混ぜない。
抽出器側の座標原点・ページ寸法を明示して正規化し、PDF.js の表示変換へ渡す。
キャプションは図表との関連を保持し、本文と重複して翻訳しない。
長い段落は翻訳用に分割しても親ブロックと全出典を維持する。細分化後の厳密な座標がなければ親領域を強調する。
全文を Markdown に平坦化してから座標を復元する方法は採用しない。

## 5. 翻訳とキャッシュ

既存 `src/translate/ollama.ts` の通信・中断・タイムアウトを利用し、PDF 用プロンプトを選べるようにする。
既存 Markdown プロンプトを既定に保ち、既存拡張の挙動を維持する。
PDF は plain text を入力・出力の基本にし、本文を命令として実行せず翻訳対象として扱う。
数値、引用、識別子、インライン数式を保持する指示と機械検査を行うが、翻訳の意味の正しさを自動保証とはしない。
検査失敗時は訳文を確定せず原文と理由を表示し、ユーザーが再試行できる。
本文中の任意 HTML は実行しない。

翻訳並列度は 1。現在ページ、次ページ、残りの文書順に未実行ジョブを優先する。
ページ移動だけで実行中の段落は中断せず、残りの順序を更新する。
文書切替・モデル変更は実行中を中断し、世代 ID によって遅れて届く結果を無視する。
一時停止は実行中の段落を完了させてから停止する。
タブごとに閲覧セッションを分け、翻訳実行枠はサーバー全体で共有する。

キャッシュキーには原文、見出し文脈、モデル名、翻訳パラメーター、プロンプト版、検査版を含める。
モデル名が同じまま実体を更新した場合に備え、キャッシュを使わない再翻訳操作を用意する。
抽出キャッシュは PDF ハッシュ、抽出器バージョン、抽出設定、中間形式バージョンで無効化する。
書き込みは一時ファイルから置換し、同じ保存先への更新は直列化する。
元 PDF はセッション中の一時ファイルとして扱い、通常終了・文書を閉じる操作で削除する。
異常終了で残った一時 PDF は次回起動時に回収する。抽出テキストと訳文はキャッシュとして残る旨を画面に表示し、文書単位で削除できる。

## 6. ローカル API と実行境界

サーバーは `127.0.0.1` にのみバインドし、起動時にブラウザを開けるコマンドを提供する。
ブラウザからの操作は同一オリジンに限定し、Host/Origin とセッショントークンを検証する。
Ollama 接続先はサーバー側設定に置き、初期版ではループバックのみ許可する。
ファイルはブラウザから PDF バイト列として送信し、クライアント指定のファイルパスを読み込まない。
上限は初期値 50 MiB・300 ページ。超過は処理開始前またはページ数判明時に明示して拒否する。
抽出同時実行は 1。待機・実行・失敗を区別し、抽出タイムアウトは初期値 10 分とする。

API の責務は、文書登録、抽出状態と正規化データの取得、セッション作成、ページ優先順位更新、翻訳停止・再開・再試行、イベント配信、キャッシュ削除。
更新配信は SSE を使い、再接続時は状態スナップショットから復元する。
Python ワーカーの stdout は構造化 JSON、stderr は診断用とする。
ワーカーを中断した場合は子プロセスを回収し、未完成の抽出結果をキャッシュに採用しない。

## 7. 失敗時の挙動

- Ollama 未起動・モデルなし: 原文を維持し、必要な対処と再試行を表示。
- 暗号化 PDF: 初期版はパスワード解除を扱わず、理由を表示。
- スキャン・文字抽出不能ページ: 「OCR 未対応」または「文章を抽出できません」と表示し、空ページを翻訳成功扱いしない。
- 混在 PDF: 抽出可能なページは使用でき、抽出不能ページは個別に警告。
- 一部の抽出失敗: 正常なページは表示し、失敗範囲を明示。壊れた JSON や未知のスキーマは読み込まない。
- 不正な座標: 当該ブロックの位置同期だけを無効にし、文章と警告を表示。
- 読み順・表分類の誤り: 原文を常に確認可能にし、抽出精度を保証した表示にしない。

## 8. 検証と受け入れ条件

1. 一段組み一般文書と二段組み論文の fixture で、左右の段が混ざらず期待するブロック順になる。
2. 本文、キャプション、図表、数式が重複・脱落せず、翻訳対象と原文表示対象に対応づく。
3. 左右クリック、ページ移動、ズーム、回転、複数ページの出典で対応箇所を確認できる。
4. ページ移動で未実行ジョブが並べ替わり、文書切替後に古い訳文が混ざらない。
5. 再読込はキャッシュを使い、原文・モデル・文脈・プロンプト変更では古い訳を流用しない。
6. Ollama 未起動、途中切断、抽出不能、上限超過、壊れたキャッシュを成功として扱わない。
7. 正規化・キュー・キャッシュ・API は自動テストし、ブラウザの左右対応は実 UI でも検証する。
8. Docling 実行と Ollama 実行はモック検証と区別して記録する。実論文の読み順と訳の品質は実物で評価し、未検証なら明記する。
9. 既存の Markdown 拡張の型検査・単体テスト・ビルドを通す。
